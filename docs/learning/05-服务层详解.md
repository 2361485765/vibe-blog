# 05 - 服务层详解

## 5.1 服务层架构

服务层位于 `backend/services/` 目录，为 Agent 层和 API 层提供底层能力。采用**单例模式** + **懒加载**的设计：

```python
# 典型的服务初始化模式
_instance = None

def init_service(config):
    global _instance
    _instance = Service(config)

def get_service():
    return _instance
```

全局服务注册在 `backend/services/__init__.py` 中：

```python
from .llm_service import LLMService
from .task_service import TaskManager

_llm_service = None
_task_manager = None
_blog_service = None
_search_service = None
_image_service = None

def init_llm_service(config): ...
def get_llm_service(): ...
def init_blog_service(...): ...
def get_blog_service(): ...
```

## 5.2 LLMService — LLM 统一客户端

**源文件**: `backend/services/llm_service.py` (707 行)

### 设计目标

统一管理所有 LLM 调用，屏蔽不同提供商的差异。

### 支持的提供商

| 提供商 | 格式 | 说明 |
|--------|------|------|
| OpenAI 兼容 | `openai` | 包括 OpenAI、Azure、阿里 DashScope 等 |
| Google Gemini | `gemini` | Google AI Studio |

### 三级模型策略

```python
class LLMService:
    def __init__(self, ...):
        self._model_config = {
            'fast': {'model': fast_model or text_model, 'max_tokens': 3000},
            'smart': {'model': smart_model or text_model, 'max_tokens': 8192},
            'strategic': {'model': strategic_model or text_model, 'max_tokens': 4000},
        }
```

通过 `TieredLLMProxy` 按 Agent 级别路由：

```python
# generator.py 中的初始化
def _proxy(agent_name):
    return TieredLLMProxy(llm_client, get_agent_tier(agent_name))

self.researcher = ResearcherAgent(_proxy('researcher'))  # → smart
self.planner = PlannerAgent(_proxy('planner'))            # → strategic
self.questioner = QuestionerAgent(_proxy('questioner'))   # → fast
```

### 核心方法

```python
class LLMService:
    def chat(self, messages, on_stream=None, caller="") -> str:
        """同步对话，支持流式回调"""
        
    async def achat(self, messages, on_stream=None) -> str:
        """异步对话"""
        
    def chat_with_model(self, messages, model_name, max_tokens, on_stream=None) -> str:
        """指定模型对话"""
```

### 限流机制

全局限流器防止并发请求触发 API 速率限制：

```python
_MIN_REQUEST_INTERVAL = float(os.environ.get('LLM_MIN_REQUEST_INTERVAL', '1.0'))

def _rate_limit():
    from utils.rate_limiter import get_global_rate_limiter
    get_global_rate_limiter().wait_sync(domain='llm')
```

### 弹性调用配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `LLM_CALL_TIMEOUT` | 600s | 单次调用超时 |
| `LLM_MAX_RETRIES` | 5 | 最大重试次数 |
| `LLM_RETRY_BASE_WAIT` | 5s | 重试基础等待 |
| `LLM_RETRY_MAX_WAIT` | 60s | 重试最大等待 |
| `LLM_MIN_REQUEST_INTERVAL` | 1.0s | 请求最小间隔 |

### 5.3.2 SmartSearchService — 智能搜索增强

**源文件**: `backend/services/blog_generator/services/smart_search_service.py` (558 行)

在基础搜索上增加智能路由和源质量评估：

- **搜索路由**: 根据主题自动选择搜索策略
- **子查询引擎**: 将复杂查询拆分为多个子查询
- **目标导向提取**: 根据写作目标从搜索结果中精确提取信息
- **来源可信度过滤**: 评估和过滤搜索结果的可信度

## 5.6 KnowledgeService — 知识库服务

**源文件**: `backend/services/knowledge_service.py` (559 行)

### 功能

实现基于文档分块的 RAG（Retrieval-Augmented Generation）管线：

1. **文档上传**: 接收 PDF/MD/TXT 文件
2. **文档解析**: 通过 FileParserService 提取文本
3. **文本分块**: 按 `KNOWLEDGE_CHUNK_SIZE`（默认 2000 字符）分块，重叠 200 字符
4. **存储**: 分块存入 SQLite
5. **检索**: 基于关键词的简单检索（非向量检索）

### 配置

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `KNOWLEDGE_MAX_CONTENT_LENGTH` | 8000 | 最大内容长度 |
| `KNOWLEDGE_MAX_DOC_ITEMS` | 10 | 最大文档条目数 |
| `KNOWLEDGE_CHUNK_SIZE` | 2000 | 分块大小（字符）|
| `KNOWLEDGE_CHUNK_OVERLAP` | 200 | 分块重叠大小 |

## 5.8 TaskService — SSE 任务管理

**源文件**: `backend/services/task_service.py` (236 行)

### 设计

采用**单例模式**的任务管理器，管理异步任务的状态和 SSE 消息队列。

### 任务生命周期

```
pending → running → completed/failed/cancelled
```

### 数据结构

```python
@dataclass
class TaskProgress:
    task_id: str
    status: str           # pending/running/completed/failed/cancelled
    current_stage: str     # 当前阶段名
    stage_progress: int    # 阶段进度 0-100
    overall_progress: int  # 总体进度 0-100
    message: str           # 人类可读消息
    results: Dict          # 中间结果
    outputs: Dict          # 最终输出
    error: Optional[str]   # 错误信息
```

### SSE 消息推送

每个任务关联一个 `Queue`，服务端不断从队列取消息，以 SSE 格式推送：

```python
def update_progress(self, task_id, stage, progress, message, **kwargs):
    event = {
        "type": "progress",
        "stage": stage,
        "progress": progress,
        "message": message,
    }
    self.queues[task_id].put(event)
```
