# 06 - 数据流与状态管理

## 6.1 SharedState — 全局共享状态

**源文件**: `backend/services/blog_generator/schemas/state.py` (404 行)

`SharedState` 是一个 `TypedDict`，是所有 Agent 之间传递数据的唯一载体。它在 LangGraph 工作流中自动流转，每个节点读取所需数据、更新自己的输出字段。

### 状态字段分组

#### 输入字段

```python
topic: str                    # 用户输入的主题
article_type: str             # problem-solution / tutorial / comparison
target_audience: str          # beginner / intermediate / advanced
audience_adaptation: str      # 受众适配：default/high-school/children/professional
target_length: str            # mini / short / medium / long / custom
source_material: Optional[str] # 用户提供的参考资料
image_style: str              # 图片风格 ID
aspect_ratio: str             # 宽高比 16:9 或 9:16
```

#### 文档知识字段

```python
document_ids: List[str]       # 用户上传的文档 ID
document_knowledge: List[dict] # 解析后的知识条目
```

#### Researcher 输出

```python
search_results: List[dict]           # 搜索结果
background_knowledge: Optional[str]   # 背景知识摘要
key_concepts: List[str]              # 核心概念
reference_links: List[str]           # 参考链接

```

#### 多轮搜索字段

```python

knowledge_gaps: List[dict]       # 知识空白

```

#### Planner 输出

```python

information_architecture: Optional[dict] # 信息架构
```

#### Writer 输出

```python

```

#### 质量控制字段


#### 增强 Agent 字段

#### 最终输出


#### 迁移特性字段


## 6.3 初始状态创建

`create_initial_state()` 函数创建工作流的起始状态：

```python
def create_initial_state(
    topic, article_type, target_audience,
    target_length, source_material=None,
    document_ids=None, image_style="", aspect_ratio="16:9",
    custom_config=None, ...
) -> SharedState:
```

这里的关键逻辑包括：
1. `max_search_count` 根据 `target_length` 动态计算
2. `trace_id` 优先使用 `task_id_context`，保证日志完整
3. 所有列表字段初始化为空列表，避免下游 `None` 问题

### 双开关机制

每个增强 Agent 受两层控制：

```python
def _is_enabled(self, env_flag: bool, style_flag: bool) -> bool:
    return env_flag and style_flag  # 两者都为 true 才启用
```

- **环境变量**：全局开关（如 `HUMANIZER_ENABLED=false` 完全禁用）
- **StyleProfile**：运行时开关（如 mini 模式关闭事实核查）

## 6.5 中间件管道

**源文件**: `backend/services/blog_generator/middleware.py` (493 行)

### 架构

```
NodeMiddleware 协议:
    before_node(state, node_name) → Optional[Dict]
    after_node(state, node_name) → Optional[Dict]

ExtendedMiddleware 基类（额外支持）:
    before_pipeline(state)  → 流水线开始前
    after_pipeline(state)   → 流水线结束后
    on_error(state, node_name, error) → 异常降级
```

### 中间件列表

| 中间件 | 职责 |
|--------|------|
| `TracingMiddleware` | 设置追踪上下文（trace_id、node_name） |
| `TaskLogMiddleware` | 记录节点开始/结束时间，生成结构化日志 |
| `ReducerMiddleware` | 状态归约（合并列表字段） |
| `ErrorTrackingMiddleware` | 记录节点异常到 `error_history` |
| `ContextManagementMiddleware` | 上下文长度估算和自动截断 |
| `TokenBudgetMiddleware` | Token 预算管理和预警 |
| `ContextPrefetchMiddleware` | 知识库文档预取 |

### 执行流程

```python
class MiddlewarePipeline:
    def wrap_node(self, node_name, fn):
        def wrapped(state):
            # 1. before_node（正序执行）
            for mw in self.middlewares:
                patch = mw.before_node(state, node_name)
                if patch: state.update(patch)
            
            # 2. 执行原始节点
            try:
                result = fn(state)
            except Exception as e:
                # 尝试降级
                for mw in reversed(self.middlewares):
                    fallback = mw.on_error(state, node_name, e)
                    if fallback: return fallback
                raise
            
            # 3. after_node（逆序执行）
            for mw in reversed(self.middlewares):
                patch = mw.after_node(result, node_name)
                if patch: result.update(patch)
            
            return result
        return wrapped
```
